Sesión 4. Plan de Pruebas de Software (Software Testing Plan)
Proyecto: Sistema de Gestión de Pedidos de una Pizzería
Stack Tecnológico: Node.js / Express, HTML5 / JavaScript Vanilla, MySQL (pizzeria)
Rol: Analista de Calidad / Líder de Calidad y Procesos (Heidy Asprilla)
Norma de Referencia: ISO/IEC 29110:2016 – Perfil Básico (Proceso SI.5: Verificación y Validación)
4.1. Objetivos del Plan de Pruebas
Validación Funcional: Verificar que la API REST en Node.js/Express procese correctamente las operaciones de consulta y registro de clientes, productos y pedidos.  Integridad de Datos: Garantizar la persistencia y coherencia de la información en las tablas relacionales (clientes, productos, pedidos, detalle_pedido) de MySQL.  
Control de Excepciones: Detectar errores de validación en la interfaz web y fallos de conexión a la base de datos antes de la entrega final.
4.2. Alcance (Scope)
Módulos a probar: Módulo de Gestión de Clientes, Módulo de Menú/Productos, Módulo de Registro de Pedidos y Detalles, y Conexión con Base de Datos MySQL.
Tipos de prueba a ejecutar: Pruebas de API REST (Endpoints HTTP), Pruebas de Integración (Node.js y MySQL) y Pruebas de Interfaz de Usuario (Formulario de Pedidos).

4.4 Resultados de la Evaluación Cross-Testing:
Un grupo par evaluó la aplicación web de la pizzería ejecutando el Plan de Pruebas sobre la rama main del repositorio GitHub (pizzeria-calidad-software). Los hallazgos documentados en el informe final son los siguientes:
Hallazgo 1 (Menor - Validación de Backend): Al enviar una petición POST a la API de pedidos con un cliente_id inexistente en la base de datos, MySQL arroja un error de restricción de llave foránea (FOREIGN KEY constraint) que no es capturado amigablemente por Express.
Acción Correctiva: Implementar un bloque try/catch con un middleware de control de errores en Node.js que responda un estado HTTP 400 con un mensaje entendible ("El cliente seleccionado no existe").
Hallazgo 2 (Aceptación - Persistencia e Interfaz): Las operaciones de consulta del menú, inserción de clientes y almacenamiento de pedidos en la base de datos pizzeria funcionan correctamente y actualizan el estado del pedido ('Pendiente', 'En preparación', 'Listo') de forma coherente.
Conclusión de Calidad: La aplicación web cumple satisfactoriamente con las actividades de verificación y validación (SI.5) del Perfil Básico de la norma ISO/IEC 29110, demostrando trazabilidad entre los requerimientos del cliente, el diseño de la base de datos MySQL y el código fuente alojado en GitHub.
